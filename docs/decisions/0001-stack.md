# 0001. Стек MVP

- Статус: Предложено
- Дата: 2026-10-26
- Обсуждение: [документ со сравнением вариантов](https://claude.ai/artifact/3YKSRNdmXW6c2UJLAZ6A5k)

## Контекст

Нужен MVP сценария «Мои места». К КТ-3 он должен открываться по ссылке у эксперта без установки (мок-данные допустимы), а дальше дорастать до продукта без переписывания и быстро переноситься в Android и на ПК, оставаясь сайтом и, при желании, мини-приложением мессенджера.

Команда маленькая: разработка на TypeScript и Python, ML на Python. Есть VPS с Docker и Caddy. Instagram и Telegram в РФ заблокированы (Telegram с апреля 2026), поэтому шаринг другу идёт обычной ссылкой с превью в любой мессенджер, а мини-приложение (MAX или Telegram) остаётся опцией на потом.

## Варианты

- A. Веб-клиент React + Vite + TypeScript: сайт и мини-приложение мессенджера одним билдом, Android/iOS через Capacitor, ПК через установку PWA или Tauri 2. Бэкенд FastAPI + Postgres/PostGIS, воркер на Python.
- B. Next.js фуллстек на TypeScript + Postgres.
- C. Expo (React Native) + Supabase.
- D. Flutter (все платформы официально, но новый язык Dart и тяжёлый веб).

## Решение

Предлагается A. Будет зафиксировано после обсуждения.

## Последствия

- К КТ-3 делается только `apps/web` на мок-данных и выкладывается статикой.
- Два языка и два деплоя, зато ML и разбор ссылок сразу на Python.
- Общая логика, типы и API-клиент живут в `packages/core`, чтобы при необходимости сделать нативное приложение на Expo без переписывания логики.
- Мини-приложение MAX требует бизнес-аккаунта (юрлицо РФ), это не задача MVP.
