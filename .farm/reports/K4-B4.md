## Решения и наблюдения

1. **Полная совместимость с веб-прототипом (`packages/core` + `handlers.ts`)**:
   - Сессия без регистрации поддерживает все способы передачи из `handlers.ts`: заголовки `X-Session-Id`, `X-Anonymous-Id`, `Authorization: Bearer <id>`, cookie `session_id`, а при их отсутствии — дефолтный бакет `default` (после `POST /me` без заголовков создаётся и запоминается дефолтная сессия, а также выставляется cookie `session_id`).
   - Координаты в `Location` отдаются в формате `{"lat": number, "lng": number}` (как в `packages/core/src/geo/geo.ts`), при этом на вход валидатор принимает как `lng`, так и `lon` (из PostGIS `PlaceMatcher`).
   - В `Vote` поле `name` сериализуется только если оно задано (в `packages/core/src/shortlist/shortlist.ts` используется `z.string().optional()`, который не принимает `null`).
2. **Пайплайн `POST /links/resolve` и честные статусы сопоставления**:
   - Ссылка сначала канонизируется (`ig:<shortcode>`, `tt:<videoId>`, `yt:<videoId>`, `tg:<channel>/<postId>` или нормализованный URL без `utm_*`, `igsh`, `fbclid` и др.). При повторном запросе той же канонической ссылки ответ отдаётся из таблицы `link_resolutions` в SQLite с заголовком `X-Cache: HIT` без повторного вызова `ExtractionPipeline`.
   - Реализован интерфейс `ExtractionPipeline` (`FakeExtractionPipeline` по умолчанию и `HttpExtractionPipeline`, отправляющий `POST {EXTRACT_SERVICE_URL}/extract` с `Authorization: Bearer {EXTRACT_SERVICE_TOKEN}`).
   - Если задан `GEO_DATABASE_URL`, для каждого извлечённого места вызывается `PlaceMatcher` из `ml/extract-lab/geo/matcher.py`.
   - **Никаких выдуманных координат**: если место не найдено в базе (`not_found`) или является сетью без указанного в посте адреса/метро (`chain_ambiguous`), возвращается элемент `Candidate` с `place: null`, `matchStatus: "not_found" | "chain_ambiguous"`, `status: "not_found" | "chain_ambiguous"`, `isChain`, `extractedName` и (для сетей) списком филиалов `branchCandidates`.
   - **Часы работы (`hours`) — только из базы**: пайплайн извлечения не передаёт часы работы; поле `place.hours` заполняется исключительно из записи места в БД (или конвертируется из тега `opening_hours` OSM при сопоставлении через PostGIS). Если в БД часов нет (`hours = null`), в ответе остаётся `null`.
3. **Расширение категорий (`museum`, `park`, `exhibition` и др.) и предложение для `packages/core`**:
   - В текущем `packages/core/src/place/place.ts` схема `placeTypeSchema` ограничена четырьмя значениями: `z.enum(['coffee', 'cafe', 'rest', 'bar'])`, а `candidateSchema` требует не-null `place: placeSchema`.
   - Чтобы не ломать существующий фронтенд (`apps/web`) и не трогать файлы вне зоны `apps/api/`, для каждого места в `place.type` отдаётся валидный базовый тип (`coffee | cafe | rest | bar`), а точная извлечённая категория сохраняется в `place.rawCategory` и `candidate.rawCategory` / `candidate.category` (`"museum"`, `"park"`, `"exhibition"` и др.).
   - **Предложение минимального расширения `packages/core` (для задачи `K4-F1`)**:
     ```ts
     // packages/core/src/place/place.ts
     export const extendedCategorySchema = z.enum([
       'coffee', 'cafe', 'rest', 'bar', 'bakery', 'fastfood',
       'museum', 'gallery', 'park', 'exhibition', 'theatre', 'cinema', 'market', 'other',
     ]);
     export const matchStatusSchema = z.enum(['exact', 'ambiguous', 'chain_ambiguous', 'not_found']);

     // В placeSchema добавить:
     rawCategory: extendedCategorySchema.optional(),

     // В candidateSchema разрешить place: placeSchema.nullable() и добавить:
     matchStatus: matchStatusSchema.optional(),
     rawCategory: extendedCategorySchema.optional(),
     extractedName: z.string().optional(),
     isChain: z.boolean().optional(),
     branchCandidates: z.array(placeSchema).optional(),
     ```
