## Решения и наблюдения

- **Реальная загрузка Москвы из Overpass API в PostGIS (порт `54329`):**
  - Запрос разбит на 4 ограниченных по памяти батча (`[maxsize:67108864][timeout:90]`) по границе `rel["name"="Москва"]["admin_level"="4"]["boundary"="administrative"] -> map_to_area` с поддержкой `HTTPS_PROXY` из окружения, паузами и повторами по зеркалам Overpass.
  - Сырые ответы сохранены в `ml/extract-lab/geo/cache/` (исключён из git через `ml/extract-lab/geo/.gitignore`, 4 файла общим объёмом 6.1 МБ).
  - **Время загрузки:** холодный прогон со скачиванием из Overpass API — **`190.11 с`** (`moscow_amenity_food`: 40.08 с, `moscow_tourism`: 42.20 с, `moscow_leisure_park`: 42.75 с, `moscow_metro_stations`: 57.28 с + запись в БД и расчёт сетей); повторная загрузка из кэша `geo/cache/` — **`3.49 с`**.
  - **Число загруженных строк по категориям (`places`, всего `13 321`):**
    - `cafe`: **4 910**
    - `fast_food`: **3 606**
    - `restaurant`: **2 645**
    - `bar`: **856**
    - `park`: **499**

    - `gallery`: **127**
  - **Станции метро и МЦК (`metro_stations`):** **276** строк.
  - **Сетевые заведения (`chain_branch_count > 1`):** **1 225** уникальных сетей (`chain_key` по нормализованному `brand` или `normalized_name`).
- **Архитектура матчера (`matcher.py`):**
  - Нормализация очищает кавычки, приводит `ё` → `е`, аккуратно снимает латинскую диакритику (`Flâner` → `flaner`, `Ladurée` → `laduree`) без повреждения кириллической `й`, убирает финальный дореволюционный `ъ` (`Пушкинъ` → `пушкин`) и удаляет родовые слова («кафе», «бар», «ресторан», «музей», «галерея», «парк» и др.), сохраняя исходные токены, если имя состоит только из родовых слов.
  - Двунаправленная транслитерация `RU ↔ EN` генерирует фонетические и побуквенные варианты как при индексации в поле `translit_name` (с отдельным `GIN gin_trgm_ops` индексом), так и при разборе входного запроса (`Flâner` ↔ `Фланер`, `Pims` ↔ `Пимс`, `Underdog` ↔ `Андердог`, `Surf Coffee` ↔ `Серф Кофе`).
  - Сеть (`chain_branch_count > 1`) без гео-подсказки (улица или метро/МЦК) **никогда** не превращается в случайный филиал и всегда возвращает `status = "chain_ambiguous"`. При наличии гео-подсказки (`--metro` в радиусе 1 500 м по `ST_Distance(geography)` или `--street` по `word_similarity`) конкретный филиал однозначно разрешается в `status = "exact"`.
- **Изоляция интеграционных тестов:**
  - Фикстура `db_conn` в `tests/test_matcher.py` создаёт на живом PostGIS из `docker-compose.geo.yml` изолированную схему `test_geo_fixture` и загружает туда 40 фикстурных мест и 12 станций метро/МЦК, благодаря чему запуск `pytest` проверяет реальные индексы PostGIS/`pg_trgm`, не затирая загруженные `13 321` место Москвы в `public.places`. При недоступности контейнера тесты помечаются `skip` с понятной причиной.
