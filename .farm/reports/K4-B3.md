## Решения и наблюдения

- **Слияние веток:** ветки `agents/K4-B1b` (извлечение через OpenRouter/Gemini/Fake, канонизация ссылок, SQLite-кэш) и `agents/K4-B2` (геоматчер `geo/matcher.py` на PostGIS + `pg_trgm`) влиты в `agents/K4-B3` без конфликтов. В `ml/extract-lab/pyproject.toml` добавлена зависимость `psycopg[binary]>=3.2` и `mypy_path = ["src", "geo"]`.
- **Сквозной пайплайн (`pipeline.py` / `src/extractlab/pipeline.py`):**
  - Принимает видеофайл и/или ссылку + подпись, проверяет SQLite-кэш (`cache_ms`), вызывает провайдера (`openrouter`, `gemini` или `fake`, `extraction_ms`), а затем сопоставляет каждое извлечённое место через `PlaceMatcher` с локальной базой PostGIS (`matching_ms`).
  - Для каждого места проставляет `resolution_status` (`exact`, `chain_ambiguous`, `ambiguous`, `not_found`), флаг `needs_user_choice` (`true` при `chain_ambiguous` и `ambiguous`) и список сматченных кандидатов с координатами из базы OSM.
  - Ветка «места нет в базе» (`not_found`) оставлена явной заглушкой `_lookup_missing_place_stub` с `TODO(K4)` без обращения к внешнему веб-поиску.
  - Учтена особенность OSM Москвы: из 13 321 заведений только у 1 579 на самой точке POI заполнен `addr_street`. Если модель извлекла адрес (без метро), а строгий фильтр `addr_street` в `PlaceMatcher` дал `not_found` из-за пустого `addr_street` в OSM, пайплайн делает проверочный запрос по названию и принимает `exact` только для уникального несетевого заведения без конфликта улицы.
  - При недоступности контейнера PostGIS в режиме `--fake` автоматически используется офлайн-матчер `InMemoryPlaceMatcher`, чтобы тесты и `--fake`-прогон работали в любой среде.
- **Формат датасета (`data/dataset.example.jsonl`):**
  - 6 фиктивных записей (`ex-01`..`ex-06`), покрывающих типы `address_in_caption`, `on_screen_text_only`, `speech_only`, `multi_place`, `chain_no_address`, `no_place`. Реальные видеофайлы в репозиторий не кладутся; относительные `video_path` разрешаются через `VIDEOS_DIR`.
- **Оценка качества (`eval.py`) и генератор отчёта (`report.py`):**
  - Считает `recall`, `precision` и `f1` по нечёткому совпадению названий (`--fuzzy-threshold`, по умолчанию `0.65`), долю верных адресов/метро, долю верных `resolution_status`, долю корректных отказов на `no_place`, латентность `p50`/`p95` и стоимость на ролик и в сумме — как в целом, так и в разрезе `case_type`.
  - Сырой вывод каждого прогона сохраняется в `runs/<timestamp>.jsonl` (добавлен в `.gitignore`).
  - `report.py` формирует `reports/eval-<timestamp>.md` с условиями прогона (режим, провайдер, модель, версия промпта, дата), сводной таблицей, разрезом по `case_type`, списком провалов с причиной (`не нашли` / `не то место` / `галлюцинация` / `не тот филиал`), примерами и автоматическим разделом **«Что не проверено»** (отмечает типы случаев с `< 5` роликами, режим `--fake`, отсутствие локальных MP4 и заглушку `not_found`).
