# Приёмка работы агента (для тимлида)

Основано на опыте фермы ЛЦТ (§6–8 передачи дежурства), обобщено под where_is_hype.

## Как принимать (без исключений)

1. Агент закончил: в `.farm/reports/BALANCER.md` задача `done` с заметкой `pushed`, ветка `agents/<ID>` есть на GitHub.
   Ферма уже прогнала `verify.sh` — вывод в `.farm/state/<ID>.verify`.
2. Для задач `build` дождись `REVIEW-<ID>` (ревью делает другая модель). Вердикт «доработать» → новая задача
   на доработку в той же зоне, с замечаниями ревьюера.
3. Прочитай отчёт и `git show --stat`. Агент должен был трогать только свою зону.
4. UI — посмотри скриншоты в `.farm/reports/<ID>-shots/` и перепроверь сам в браузере.
5. Влей: `git rebase main` в ветке агента, конфликты разрешай сам, сохраняя обе стороны; прогони проверки;
   `git merge --ff-only agents/<ID>`. Мелкие недочёты доправь сам маленьким коммитом в ветке агента.
6. Запиши итог в журнал проекта (что влито, коммит, что осталось).

## Как резать задачи

- Одна задача — одна зона файлов. Два агента на один файл не запускать.
- В задаче: цель, зона, критерии готовности, как проверить. Шаблон — любой файл в `.farm/tasks/`.
- Ресёрч и штурм — отдельные задачи с отчётом-результатом, без кода.
- Аудиты делать ролями: дизайнер, жюри/инвестор, новичок, сеньор-разработчик, QA. Разные модели на разные роли.

## Чего не делать

- Не вливать без проверок и без ревью другой моделью.
- Не запускать параллельно задачи с пересекающимися зонами.
- Не возвращать уже признанные проблемы.
- Не тратить платные модели на большие задачи.
