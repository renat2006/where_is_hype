# P04 — Базовые компоненты shared/ui
Цель: набор компонентов «Зин» со всеми состояниями, из которых собираются экраны.

Макеты: `docs/design/zin/Components.dc.html` (все состояния), `Stress.dc.html` (200% шрифта, медленная сеть).

Сделать в `apps/web/src/shared/ui/<name>/` (каждый со своим `index.ts`): `button` (primary, secondary, text, map; обычная, нажата, фокус, неактивна, загрузка), `chip` и `chip-group` (одиночный и множественный выбор — для часа, типа, чека), `switch`, `text-field` (ссылка и поиск, подсказка, ошибка), `sheet` (peek 96 / half 50% / full, перетаскивание, клавиатура), `toast` с `useToast` (действие «Отменить», 5 с, счётчик моно), `error-note`, `offline-banner`, `skeleton`, `empty-state`, `avatars` (инициалы стопкой, цвет по хэшу имени из 3 цветов наклеек), `segmented` (Авто · День · Ночь). Иконки — `lucide-react`.

Страница `/ui-kit` (`pages/ui-kit`) показывает все компоненты и состояния в обеих темах — по ней ревьюер сверяет с макетом.

Правило чистоты: никаких поворотов, скотча и рукописного текста в этих компонентах; тень `raised` только у primary.

Зона: `apps/web/src/shared/ui/**` (кроме sticker, decor, logo), `apps/web/src/pages/ui-kit`, `apps/web/package.json`, `pnpm-lock.yaml`. Тесты на поведение (toast, sheet, chip-group).

Общее для всех задач прототипа:
- База — ветка `feat/prototype`: там PR #1 (стек), `docs/product/mvp-scope.md` (US1–US10) и `docs/design/` (дизайн-система «Зин»). После ревью ферма сама вольёт твою ветку в `feat/prototype`.
- Прототип работает в браузере на моках MSW (`VITE_API_MOCKS=true`), бэкенд не трогаем. Тексты интерфейса — как на макетах.
- Прочитай `CLAUDE.md`, `docs/design/README.md` (особенно «стиль помогает контенту») и макеты, указанные ниже. Ширина 360 px, день и ночь.
- Новую зависимость добавляй только если она названа в задаче; `pnpm-lock.yaml` обновляй через `pnpm install`, руками не правь.
- Нужна вещь из чужой зоны, которой ещё нет, — сделай минимальную заглушку у себя и опиши в отчёте, в чужую зону не лезь.
